# P0 Event Log Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Independently replay local evidence and verify commit scores.
**Architecture:** Journal owns all engine mutations; replay reconstructs provenance; public receipts commit to a local journal prefix.
**Tech Stack:** TypeScript, Node built-ins, VS Code API; no new runtime dependencies.
**Spec:** docs/superpowers/specs/2026-10-11-p0-event-log.md

## Global Constraints
- Keep rule-based-v0.1 and receipt/v2 compatibility.
- Keep full source evidence local and preserve legacy files.
- Reject corrupt/incomplete evidence; no silent reset.
- No P1 or additional remote checkpoints.

## Review Focus
- Restart must reconstruct hidden cut and nearby-edit state.
- Paused/offline mutations must become unverified events.
- Write failures and simultaneous windows must not emit trusted-looking receipts.
- Partial staging must not inherit mismatched buffer scores.
- Later journal events must not invalidate an older receipt prefix.

### Task 1: Journal and replay
Files: create extension/src/event-log.ts, extension/src/event-log.test.ts.
Interfaces: EventReplay accepts validated events and exposes engine, header, seq, tip and session metadata. EventJournal.open(filename) loads/replays; ensure/apply/reconcile/save/session append events; close releases lock; flush syncs disk. replayJournal(filename, commitment?) independently validates the entire log or requested prefix.
- [x] Write failing tests for >1,000 events, Unicode/move replay, hash/range/sequence tampering, restart, incomplete lines, locks and I/O failure.
- [x] Run build/tests and confirm new functionality is absent.
- [x] Implement strict versioned canonical events, deterministic replay and append-only persistence.
- [x] Run journal tests and existing suite; commit.

### Task 2: Commit replay verification
Files: create extension/src/replay-proof.ts, extension/src/replay-proof.test.ts, extension/scripts/verify-event-log.cjs; modify extension/src/proof.ts.
Interfaces: commitMetrics(engine, manifest, readContent) returns ReceiptBody.metrics; verifyReplayReceipt(root, receipt, key, filename) returns replay-verified metrics, file reports and redacted segment offsets.
- [x] Write failing tests for signed fabricated metrics, wrong/missing commitments, tampered prefixes, valid suffixes, partial staging and legacy receipts.
- [x] Implement independent verification and CLI; declare public verification scope.

- [x] Add integration assertions that baseline/edit/save/stop persist complete journal events and restore after restart; prove corrupt storage blocks receipts and legacy scores are not imported.

## Execution results

- Baseline: 16 tests passed before implementation.
- Final validation: 24 tests passed; VSIX 0.4.0 packaged successfully.
- Independent review found duplicate startup and stale-lock recovery races. Both reproduced with failing tests, fixed, and verified by the full suite.
- Legacy scores restart as unverified because missing events cannot be reconstructed. Legacy files are retained.
- Crash during lock recovery can leave a recovery guard requiring manual inspection; automatic removal would weaken single-writer safety.
